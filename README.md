# PHPStan Baseline Highlighter

Плагин для IDE на IntelliJ Platform показывает записи PHPStan baseline возле объявлений классов, методов и именованных функций: значок в гутере, подсказка и переход к записи в NEON. Работает без запуска PHPStan, PHP CLI, Docker и других внешних процессов.

PHP-поддержка подключается опциональными адаптерами: **JetBrains PHP** (`com.jetbrains.php`) и **PHP for OpenIDE** (`ru.openide.openphp`, в том числе в Ракете). Общая часть не использует API конкретного PHP-плагина. Без обоих адаптеров доступны индекс, настройки и список записей файла; для маркеров объявлений нужен один из поддерживаемых PHP-плагинов.

Baseline фиксирует исключения, поэтому маркер **не подтверждает наличие нарушения в текущем коде**. Плагин не изменяет baseline и не подсвечивает точные строки ошибок.

## Установка и настройка

1. Скачайте ZIP из [последнего релиза](https://github.com/pastila/phpstan-baseline-highlighter/releases/latest) или соберите `build/distributions/phpstan-baseline-highlighter-0.1.16.zip` из текущего кода.
2. Откройте **Settings → Plugins → ⚙ → Install Plugin from Disk** и выберите ZIP целиком.
3. В проекте откройте **Settings → Languages & Frameworks → PHPStan Baseline Highlighter**.
4. Выберите или создайте профиль. Нажмите **Import from PHPStan config…** и выберите `.neon` или `.neon.dist` нужной конфигурации либо добавьте baseline кнопкой **+**. Проверьте строки в таблице и нажмите **Apply**.
5. Проверьте диагностику и примеры вычисленных путей. При пустой базовой директории относительные `path` разрешаются относительно каталога baseline.

Подключайте только baseline нужной PHPStan-конфигурации. Несколько источников и произвольные имена файлов поддерживаются.

В списке **Profile** можно создать отдельные наборы, например для основного анализа и CI, скопировать текущий набор, переименовать или удалить профиль. **Apply** сохраняет все наборы и активирует выбранный профиль: индекс, маркеры, список файла и MCP-поиск используют только его источники. Переключение списка до Apply редактирует черновик; **Reset** отменяет несохранённые изменения всех профилей. Названия уникальны без учёта регистра, последний профиль удалить нельзя.

При обновлении прежний список источников переносится в профиль **Default** с сохранением отключённых строк, базовых директорий и общего переключателя плагина. Профили и активный выбор хранятся локально в workspace проекта. Один baseline может присутствовать в разных профилях с разными базовыми директориями; повторы проверяются внутри каждого набора. Импорт дополняет выбранный профиль, а смена профиля отменяет незавершённый импорт. Нижняя область диагностики подписана именем уже применённого профиля. Ссылки MCP из предыдущих настроек требуют повторного поиска после Apply.

Импорт читает выбранный файл и его вложенные `includes`: блочные списки и однострочные списки в скобках, например `includes: [config/rules.neon, config/baseline.neon]`. Относительные пути считаются от каталога содержащего их конфига. Повторные пути обрабатываются один раз; циклы пропускаются с сообщением. Baseline определяется по содержимому `parameters.ignoreErrors` и проверяется обычным парсером плагина. Пустые baseline поддерживаются, а конфиги сервисов не добавляются как источники.

Найденные файлы появляются в таблице для проверки. Импорт дополняет список: существующие строки, отключённые источники и заданные базовые директории сохраняются. Новые строки используют каталог самого baseline как базовую директорию. До **Apply** сохранённые настройки и индекс не меняются; **Reset**, закрытие настроек и кнопка отмены прерывают выполняющийся импорт.

Для обновления набора после изменения `includes` повторите импорт в нужном профиле. Для другой PHPStan-конфигурации создайте отдельный профиль и импортируйте её источники. Постоянная синхронизация состава источников пока не реализована. Сами подключённые baseline после Apply продолжают обновляться обычным способом.

Отчёт импорта показывает недоступные файлы, циклы, неподдержанные записи и превышение ограничений. PHP-конфиги, параметры `%…%`, маски и URL не исполняются и не раскрываются. Файл с `ignoreErrors`, который не является поддержанным отдельным baseline, пропускается с причиной; поддержанные соседние источники сохраняются в результате. Импорт работает в фоне, читает текущие документы с несохранёнными изменениями и не требует PHP-плагина. Ограничения: 512 файлов, глубина `includes` до 64, до 512 подключений в одном файле, 16 Ми символов на файл и 64 Ми суммарно. Показываются первые 20 сообщений с общим счётчиком.

Пример для проекта с расположением:

```text
project/
  config/phpstan-baseline.neon   # path: ../src/Service.php
  src/Service.php
```

Достаточно добавить `config/phpstan-baseline.neon`, оставив базовую директорию пустой. Настройки хранятся локально в workspace проекта; пути внутри проекта сохраняются относительно его корня.

Для Ракеты можно выбрать нужный `.phpstan*.neon` из `app/raketa/code_quality` при импорте либо добавить подключённые baseline вручную. У них базовую директорию обычно можно оставить пустой. Абсолютные контейнерные пути `/web/...` не преобразуются автоматически.

## Работа в редакторе

- Маркер класса объединяет его записи, включая записи методов.
- Маркер метода показывает записи, в которых метод явно назван владельцем диагностики.
- Маркер именованной функции показывает записи, где владельцем явно названа эта функция. Глобальные функции и функции из разных пространств имён сопоставляются по полному имени, без учёта регистра.
- При единственной записи клик открывает и выделяет её сообщение. При нескольких появляется список источников.
- Действие **Show PHPStan Baseline Entries for File** доступно через контекстное меню PHP-файла и Find Action. Оно показывает и записи без определённого владельца.
- Изменения baseline и PHP-кода подхватываются, в том числе до сохранения файлов. Ошибка формата убирает записи некорректного источника до исправления.
- Кнопка перечитывания в настройках обновляет применённые источники и диагностику. Видимость значков также регулируется через **Editor → General → Gutter Icons**.

Например, `Method App\Service::save() has ...` относится к объявлению `save()`. Сообщение `Call to an undefined method App\Other::run()` не позволяет определить метод, в котором сделан вызов: плагин не ставит маркер на объявление вызываемого `run()`.

Также распознаются `Public method "App\Service::save()" is never used` и `Return type (…) of method App\Service::save() should be compatible with return type (…) of method App\ParentService::save()`. Во втором случае запись относится к первому, дочернему методу; метод родителя не получает её маркер.

Архитектурные сообщения PHPat `FQN should not exist`, `should have only one public method`, `should be named matching the regex …`, `should implement …` и `should extend …` относятся к классу слева. Имя правила перед `FQN` необязательно. Указанный справа интерфейс, родитель или regex не становится владельцем записи; regex из текста сообщения не исполняется.

Сообщения `Class FQN implements generic interface … but does not specify its types: …`, `Class FQN extends generic class … but does not specify its types: …` и `Class FQN has PHPDoc tag @… …` относятся к классу слева. Имя метода в PHPDoc `@method` не создаёт привязку к методу. Сообщения о вызове конструктора, отсутствующем классе или неверном регистре ссылки не определяют владельца: в них назван используемый класс, а не место нарушения.

У сообщений `Property FQN::$property …` класс распознаётся только для известных диагностик объявления: отсутствующий тип или тип элементов, generic-параметры, неизвестный класс типа, неиспользуемое свойство или вариант его типа, несовместимое значение по умолчанию. Присваивание, `isset`, `empty` и `??` относятся к месту обращения: класс свойства не считается владельцем такой записи. При единственном классе файла используется `file_only` с пояснением; при нескольких типах запись остаётся в списке файла и поиске MCP по файлу или идентификатору. Нераспознанные формулировки о свойствах также остаются на уровне файла.

Если владелец неизвестен, запись может отображаться возле единственного класса файла с соответствующим пояснением. В файле с несколькими классами она остаётся доступна через действие для файла. Если указанный метод отсутствует, запись остаётся в сводке указанного класса.

Для функций распознаются сообщения `Function App\run() has parameter …`, `has no return type specified`, `has invalid return type …`, `return type has …` и `should return …`. Замыкания и стрелочные функции не сопоставляются. Упоминание вызываемой функции в `Parameter … of function …`, `Call to function …`, `Function … not found` или `Function … invoked …` не определяет владельца. Если явно названная функция отсутствует в целевом файле, запись остаётся в списке файла и не переносится к классу или методу. Неизвестного владельца по единственной функции файла плагин не угадывает.

Поле `count` показывается как ожидаемое количество совпадений анализатора. Это не число записей и не количество отмеченных строк.

Поддержанные формулировки, ограничения и фактические привязки на подключённых baseline Ракеты: [список поддержки](RAKETA_BASELINE_SUPPORT.md) и [полная матрица идентификаторов](RAKETA_BASELINE_IDENTIFIERS.md).

## Инструменты MCP

При установленном и включённом **MCP Server** (`com.intellij.mcpServer`) плагин добавляет четыре инструмента в MCP-сервер IDE. Отдельный сервер не нужен. Подключите MCP-клиент через **Settings → Tools → MCP Server** и обновите список инструментов клиента после установки плагина. Без MCP Server обычные функции плагина продолжают работать.

| Инструмент | Аргументы и результат |
|---|---|
| `find_baseline_entries` | `filePath`, `className`, `functionName` и/или точный `identifier`; необязательные `methodName`, `offset` (0), `limit` (50, максимум 200). `functionName` нельзя совмещать с `className` или `methodName`. Возвращает записи, общее число и `hasMore`. |
| `open_baseline_entry` | `entryId` из поиска. Открывает сообщение в baseline и выделяет его текущий диапазон. |
| `get_baseline_status` | Без аргументов. Показывает `activeProfileId`, `activeProfileName`, состояние индекса, источники активного профиля, ошибки разбора и отсутствующие целевые файлы. |
| `get_error_identifier_info` | `identifier`. Возвращает группу ошибки, наличие в каталоге, пояснение и ссылку на документацию, если они доступны. |

Пример поиска по классу и методу:

```json
{"className":"App\\Service","methodName":"save","limit":20}
```

Для функции укажите полное имя без скобок:

```json
{"functionName":"App\\run","limit":20}
```

Укажите хотя бы `filePath`, полное имя `className` или `functionName`, либо `identifier`; `methodName` требует `className`. `functionName` нельзя совмещать с `className` или `methodName`, но можно ограничить по файлу и идентификатору. Относительный `filePath` считается от корня проекта. Фильтры применяются совместно. Поиск по классу, методу или функции использует текущие PHP-объявления и те же правила, что значки в гутере; для него нужен PHP-адаптер. Поиск по файлу или идентификатору работает и без него, включая записи без известного владельца. `identifier` сравнивается целиком с учётом регистра; один этот фильтр ищет по всем подключённым baseline. Пагинация применяется после фильтров. Упоминание класса или функции как вызываемой зависимости не делает их владельцами записи.

Ответ содержит `entryId`, `baselineFile`, строку `line` (с 1), диапазон `startOffset`/`endOffset` (UTF-16, конец не включён), `targetFile`, поля владельца `className`, `methodName`, `functionName`, тип привязки `binding`, сообщение и исходный шаблон, `identifier` и `count`. Для функции `className` и `methodName` равны `null`; для класса или метода `functionName=null`. Поля `errorGroup`, `knownIdentifier`, `explanation` и `documentationUrl` добавляют справку по типу ошибки. В поиске по файлу `binding=file`, а поля владельца являются подсказками из сообщения. В поиске по объявлениям `binding` имеет значения `none` (обычная привязка), `file_only` (единственный класс файла) или `method_missing` (метод отсутствует, запись осталась у класса).

При `state=updating` повторите запрос после завершения индексации; пустой ответ в этом состоянии не означает отсутствия записей. `state=disabled` означает отключённый плагин. Ошибки отдельных baseline смотрите через `get_baseline_status` — неверный источник не попадает в результаты. Диагностика ограничивает примеры ошибок и отсутствующих путей до 20 на источник, сохраняя полные счётчики.

`entryId` действует в текущем открытом проекте; плагин хранит до 1000 последних найденных записей. После перезапуска, истечения ID или изменения записи выполните поиск снова. Переход учитывает несохранённые сдвиги строк и возвращает ошибку, если запись изменилась, исчезла или её источник отключён. Инструменты не запускают PHPStan и не редактируют файлы.

## Справка по типам ошибок

В подсказке возле значка показываются группа идентификатора и краткое пояснение, если оно есть в справочнике. В списке записей можно искать по идентификатору, сообщению и пути источника. Справка под списком обновляется при выборе строки; ссылка **Документация PHPStan** открывает официальную страницу в браузере только по нажатию.

При единственной записи клик по значку по-прежнему сразу открывает baseline. **В самом `.neon` наведите мышь на значение `identifier` или текст `message`**: стандартное окно документации IDE показывает идентификатор, группу, пояснение и ссылку на PHPStan. Можно также поставить туда курсор и вызвать **Quick Documentation** (обычно Ctrl+Q). Если автоматическая документация по наведению отключена в настройках IDE, используйте это действие. Для списка со справкой по-прежнему доступно **Show PHPStan Baseline Entries for File**, в том числе для одной записи.

Подсказки NEON используют текущий текст документа, включая несохранённые изменения; подключать baseline в настройках для них не обязательно. Для встроенной справки дополнительные плагины NEON и PHP не требуются. Поддерживаются произвольные имена файлов с расширением `.neon` и тот же формат baseline, что описан ниже. Наведение на комментарий, `path` или запись без `identifier` не создаёт справку. Для подсказки проверяется текущая запись; ошибки в других частях файла диагностирует полный фоновый индекс. Неизвестный идентификатор показывается без предположительной ссылки на сайт PHPStan. Текст NEON и baseline не изменяется.

В значении `path` доступен **Ctrl+клик** или **Go to Declaration** (обычно Ctrl+B): IDE откроет указанный файл. Относительный путь считается от каталога baseline; если для этого источника задана базовая директория, используется она. Внешний вид NEON не меняется, дополнительные значки не добавляются. Переход ведёт к файлу: точной строки текущего нарушения baseline не хранит. В plain-text NEON при удержании Ctrl подчёркивается только само значение пути, без кавычек, комментария и соседних строк. Для этого используется точечная ссылка стандартного PSI API; новый синтаксический анализатор не нужен. Запросы сбора ссылок без позиции курсора ничего не сканируют. В NEON с отдельным синтаксическим плагином старый обработчик используется только для токена, полностью лежащего внутри значения `path`: крупные текстовые элементы не превращаются в ссылку.

Переход по `path` и справка встроенных идентификаторов вычисляются по запросу. Обрабатываются только первые 64 строки заголовка (до 8192 символов UTF-16) и блок текущей записи (до 32 строк / 32768 символов, строка не длиннее 16384 символов). Кэшируются заголовок и последняя запись. При превышении лимитов функция для этой позиции пропускается. Полный файл при наведении не копируется и не разбирается, классы/методы не ищутся, обхода проекта нет. Дополнительный поиск объявлений PHPat описан ниже.

Для Ctrl+наведения выполняется точный поиск только в уже загруженном VFS-кэше IDE, без принудительной синхронизации файловой системы. Если цель ещё не известна IDE, ссылка временно недоступна: дождитесь обычной синхронизации проекта или обновите файлы средствами IDE. Эти ограничения сохраняют быстрый отклик, в том числе для отсутствующих и сетевых путей. Обычное открытие файла не запускает проход по всем `path`.

Плагин содержит снимок [официального каталога PHPStan](https://phpstan.org/error-identifiers) из 1162 идентификаторов от 13 ноября 2026 года. Для известных идентификаторов формируется ссылка `https://phpstan.org/error-identifiers/<identifier>`. Для семи частых ошибок есть пояснения на русском и английском: `missingType.iterableValue`, `missingType.generics`, `missingType.return`, `missingType.parameter`, `argument.type`, `return.type`, `method.notFound`. Например, [missingType.iterableValue](https://phpstan.org/error-identifiers/missingType.iterableValue) объясняет отсутствие типа элементов коллекции.

Справочник работает без сети и независимо от установленной версии PHPStan; страницы сайта могут описывать более новую версию анализатора. Неизвестные и пользовательские идентификаторы сохраняются и участвуют в поиске, но получают `knownIdentifier=false`, `documentationUrl=null` и `explanation=null`. У известного идентификатора без встроенного пояснения есть ссылка, а `explanation=null`. При отсутствии `identifier` плагин не угадывает его по сообщению. Группа вроде `missingType.*` обозначает семейство, а не серьёзность нарушения.

Пример поиска по типу ошибки или запроса справки в MCP:

```json
{"identifier":"missingType.iterableValue"}
```

Разработчик может вручную обновить снимок командой `python3 tools/update-error-identifiers.py` (нужна сеть). Скрипт читает имена из поискового каталога phpstan.org, не исполняет JavaScript и при неожиданном формате прекращает работу до записи файла. Открытие подсказок, списков и вызовы MCP ничего не загружают.

### Объявления правил PHPat

Для `identifier: phpat.…` доступен **Ctrl+клик / Go to Declaration** к PHP-методу правила или поддержанному условию YAML. В карточке выбранной записи ссылка **Объявление правила** открывает цель или список при совпадении имён. В Quick Documentation ссылки показывают фрагмент исходного кода; стандартное действие **Go to Source** открывает его в редакторе. Переход к исходному коду доступен и прямо из справки baseline, если найдена одна цель.

Плагин находит конфигурации `.neon` и `.neon.dist` в индексе проекта, прослеживает их `includes` до открытого baseline и читает классы сервисов с тегом `phpat.test`. Явное подключение `vendor/phpat/phpat/extension.neon` не обязательно: поддерживается и установка расширения через Composer extension installer. Учитываются публичные методы с атрибутом `PHPat\Test\Attributes\TestRule` (включая alias) и методы `test…`, а также унаследованные правила. Имена преобразуются по алгоритму PHPat 0.12: например, `test_domain_dependencies` соответствует `phpat.testDomainDependencies`. При коллизиях одного идентификатора доступны все найденные объявления.

Если метод объявляет возврат `array`, `iterable`, `Generator`, `Traversable` или `Iterator`, совпадение префикса идентификатора показывает его как **возможный генератор правил**. Это предположение по имени набора, а не проверка наличия конкретного динамического элемента.

Для декларативной YAML-конфигурации архитектуры доступен переход к **возможному условию**. В зарегистрированном классе генератора должен быть метод `getYamlPaths()` с единственным `return` статического массива путей: например, `return [__DIR__ . '/../config/architecture.yaml'];`. Поддерживаются строки в одинарных кавычках с `__DIR__` и абсолютные Unix-пути, несколько YAML-файлов, наследование и переопределение метода путей. Относительный путь считается от файла, где объявлен `getYamlPaths()`; каталоги проекта в поисках YAML не обходятся.

Поддержанное соглашение использует `contexts`, `layer_templates`, `context_structure` и `context_group_rules`. Например, `phpat.architectureRulesSalesOrdersDomainServiceDependencies` ведёт к `layer_templates.Domain.Service.dependencies`, если объявлен контекст `Sales\Orders`. Для слоёв распознаются `onePublicMethod`, `naming`, `dependencies`, `implements` и специальные `canImplementButShouldNotDependOn`; имена нормализуются по правилам PHPat. Более поздний YAML-файл заменяет объявленную в нём секцию целиком. При совпадении нескольких условий доступны несколько целей.

Ctrl+клик, ссылка в карточке и Quick Documentation используют эти же цели и точную позицию ключа YAML. Подсказка явно обозначает кандидата: соответствие основано на структуре YAML и соглашении об именах, без выполнения PHP или проверки реализации генератора. При неизвестном правиле, динамических путях, отсутствующем файле или неподдержанном YAML сохраняется переход к PHP-генератору. Якоря, aliases, YAML-теги, многострочные значения и вычисляемые пути не интерпретируются. `global_rules`, правила межконтекстных вызовов и другие соглашения генерации пока не сопоставляются с YAML.

YAML читается из текущих документов, включая несохранённые правки; индекс условий кэшируется с инвалидированием при изменении документов и VFS. На генератор допускается до 32 YAML-путей, до 262144 символов на файл и до 1048576 символов суммарно, глубина вложения до 64 и до 50000 потенциальных правил. При превышении ограничений используется PHP-генератор.

Поиск требует JetBrains PHP или PHP for OpenIDE и завершённой индексации. Используются индекс имён NEON и индексы PHP-классов; обхода PHP-файлов проекта нет. Результаты кэшируются и сбрасываются при изменениях конфигураций, PHP, состава файлов или корней проекта. NEON читается из текущих документов, включая несохранённые изменения; PHP PSI обновляется после обычного commit документа средствами IDE. На холодном запросе PHPat читаются конфигурации до 262144 символов каждая. Большие конфигурации, динамические параметры в `includes`/имени класса, glob-пути и вычисляемые фабрики не обрабатываются. PHP, PHPStan и регулярные выражения сообщений baseline не запускаются. Настройки источников baseline остаются прежними.

## Поддерживаемый формат

Ограниченный структурный парсер читает стандартные генерируемые NEON baseline:

```neon
parameters:
    ignoreErrors:
        -
            message: '#^Method App\\Service\:\:save\(\) has no return type specified\.$#'
            identifier: missingType.return
            count: 1
            path: ../src/Service.php
```

Обязательны однострочные `message` и `path`; `identifier` и положительный `count` необязательны. Поддерживаются комментарии, табы/пробелы, LF/CRLF, Unicode и одинарные/двойные кавычки NEON. Пустой baseline может содержать `ignoreErrors: []`.

Не поддерживаются маски и подстановки параметров в путях, `paths`, `messages`, `rawMessage`, многострочные скаляры, PHP-конфигурации и другие формы NEON. Если источник содержит ошибку или неподдерживаемую форму, его записи не включаются в индекс, а причина появляется в настройках.

Для определения владельца распознаются буквальные шаблоны сообщений, включая определения методов, известные диагностики объявлений свойств и архитектурные требования PHPat. Произвольные PCRE не исполняются; сообщения с непонятными выражениями остаются записями уровня файла. Диагностики объявлений свойств агрегируются на уровне класса.

Буквальный шаблон должен начинаться с `^`; конечный `$` необязателен: поддерживаются и `#^literal$#`, и `#^literal#`. Весь текст шаблона проверяется до закрывающего разделителя. Группы, альтернативы, классы символов, подстановки, незакрытые шаблоны и модификаторы после разделителя не декодируются даже при буквальном начале; владельца по такому началу плагин не угадывает. Экранированные знаки, включая разделитель и буквальный `$`, читаются как текст.

## Разработка

Нужны JDK 21 и доступ к репозиториям Gradle/Maven/JetBrains при первом запуске. В репозитории есть Gradle Wrapper; системный Gradle не требуется. Kotlin 2.3.0, IntelliJ Platform Gradle Plugin 2.16.0.

```bash
./gradlew test buildPlugin
./gradlew runIde
```

По умолчанию сборка использует SDK PhpStorm 2025.2.6.2 и запускает тесты JetBrains-адаптера. Это SDK сборки, а не обязательное требование к пользовательской IDE. Объявленный диапазон IDE: ветки 252–263. Проверка API более новой IDE выполняется отдельно и не заменяет ручную проверку интерфейса.

Для компиляции OpenIDE-адаптера сборка скачивает PHP for OpenIDE 0.9.9 с сайта поставщика и проверяет SHA-256. SDK сохраняется в `.intellijPlatform/sdk`; его JAR используются только как `compileOnly` и **не включаются в ZIP плагина**. Вместо загрузки можно передать `-PopenPhpPluginPath=/path/to/php-for-openide`, указав установленный плагин с каталогом `lib`.

Можно использовать установленную IDE вместо загрузки дистрибутива:

```bash
./gradlew buildPlugin -PlocalIdePath=/absolute/path/to/PhpStorm
./gradlew verifyPlugin -PverificationIdePath=/absolute/path/to/PhpStorm
```

Для сборок IDE на JDK 25 запускайте Gradle соответствующим JDK. Опция `localIdePath` меняет SDK сборки, а `verificationIdePath` — только IDE для Plugin Verifier.

В окружении с уже загруженной IDEA Ultimate и PHP-плагином поддерживается вариант:

```bash
./gradlew test buildPlugin --offline \
  -PplatformType=IU -PplatformVersion=2025.2.6.2 \
  -PphpPluginVersion=252.28539.13
```

Он использован для первой проверки fixture-тестов. Зависимости Ultimate и JSON для такой тестовой IDE добавляются сборкой; пользовательский PhpStorm не изменяется.

### Проверка альтернативного PHP-плагина

`phpBackend` выбирает тестовое окружение: `jetbrains` (по умолчанию), `openphp` или `none`. Каждый выпускаемый ZIP содержит оба опциональных адаптера независимо от выбранного режима тестов.

```bash
./gradlew test -PlocalIdePath=/path/to/compatible/IDE \
  -PphpBackend=openphp -PopenPhpPluginPath=/path/to/php-for-openide \
  -PjetBrainsPhpPluginPath=/path/to/JetBrainsPHP
```

В этом режиме JetBrains PHP нужен только как SDK для компиляции второго адаптера; в тестовую IDE он не устанавливается. Для режима `none` задайте те же пути SDK, `-PphpBackend=none` и обычную IDE: отдельный тест проверяет загрузку и чтение baseline при отсутствии обоих PHP-плагинов.

Gradle-плагин JetBrains не узнаёт код продукта `RK`. Для тестов на установленной Ракете есть вспомогательный скрипт:

```bash
python3 tools/prepare-local-sdk.py /path/to/Raketa .intellijPlatform/local-sdk
./gradlew test -PlocalIdePath="$PWD/.intellijPlatform/local-sdk" \
  -PphpBackend=openphp -PopenPhpPluginPath=/path/to/php-for-openide \
  -PjetBrainsPhpPluginPath=/path/to/JetBrainsPHP \
  -PtestFrameworkVersion=262.11879.100
```

Скрипт создаёт локальное представление SDK с симлинками и совместимыми для структурного анализатора Gradle метаданными. Установленная Ракета не изменяется. Версию test framework нужно выбирать под конкретную сборку платформы; указанная версия использована с Raketa 2026.2.4 / 262.11879.SNAPSHOT. Для неё Gradle запускается на JDK 25.

### Проверки

```bash
./gradlew test
./gradlew verifyPluginStructure verifyPluginProjectConfiguration
./gradlew verifyPlugin -PverificationIdePath=/absolute/path/to/PhpStorm
./gradlew benchmarkBaselines -PbaselineDirectory=/path/to/directory/with/baselines
```

`test` проверяет парсер, владельцев сообщений, пути, PHP PSI, обновление индекса и переходы в изолированной IDE. Отчёты разделены по режимам: `build/reports/tests/jetbrains/index.html`, `openphp/index.html` и `none/index.html`. Benchmark читает файлы и измеряет JVM-ядро; он не запускает анализатор и не является замером памяти всего IDE-процесса. Для benchmark выбирайте каталог baseline без больших деревьев зависимостей.

MCP Server берётся из SDK сборки; при необходимости задайте `-PmcpServerPluginPath=/path/to/mcpserver`. Для проверки без MCP Server используйте `-PmcpServerEnabled=false` вместе с этим путём: API останется только в compile classpath, сервер не устанавливается в тестовую IDE. В этом режиме исключаются MCP-тесты, остальные выполняются как обычно. Для полной проверки без PHP-адаптеров дополнительно задайте режим `none` и пути SDK PHP-плагинов, описанные выше.

Результаты первой проверки, измерения и оставшиеся ручные проверки: [VALIDATION.md](VALIDATION.md). План и критерии приёмки: [plan.md](plan.md).
