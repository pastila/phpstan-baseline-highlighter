# Проверки плагина

## Диапазон Ctrl-подсветки 0.1.6

Исправлено подчёркивание всего plain-text NEON при Ctrl-наведении на `path`. Старый `GotoDeclarationHandler` получал цель правильно, но IDE выбирала диапазон исходного PSI-элемента, который в plain text охватывает весь файл. Теперь для `PsiPlainTextFile` зарегистрирован `PsiSymbolReferenceProvider`: он создаёт одну ссылку по offset-hint с явным диапазоном содержимого `path`, исключая кавычки и комментарий. Модель файла и синтаксический анализатор не заменялись.

Старый обработчик оставлен для NEON-плагинов, но принимает только PSI-токен, полностью лежащий в сыром диапазоне значения `path`. Крупные PSI-элементы не перехватывают штатные ссылки. Разрешение пути и настроенная базовая директория вынесены в общий `BaselinePathNavigation`; lookup по-прежнему использует только VFS-кэш. Для plain-text ссылки цель представлена собственным `NavigatableSymbol`/`NavigationTarget` и публичным `NavigationRequest.sourceNavigationRequest`. При Ctrl-наведении целевой PHP PSI не создаётся; подсказка показывает имя и путь файла. Внутренние API преобразования PSI в символы не используются.

Регрессионные проверки запрашивают штатные данные `GotoDeclarationAction.getCtrlMouseData` в фоновом read action и сравнивают **весь список диапазонов** с точным диапазоном пути, а не только попадание курсора внутрь. Проверены некавыченный путь, оба вида кавычек, Unicode escape, соседние записи и фактическое открытие файла. Проверка запроса без offset запрещает любые обращения к PSI-файлу и подтверждает пустой результат. Ссылка, полученная до изменения документа, не разрешается после правки.

Ограниченный разборщик не изменён: на 25 000 записей / 2 850 028 символов по-прежнему прочитано 389 символов, прогретый p95 на SDK 252 в этом прогоне ≈ 0,04 мс. Создание ссылок не перечисляет записи файла, не добавляет аннотации и не выполняет поиск по проекту. Это замер разборщика, а не всей IDE.

Собран `build/distributions/phpstan-baseline-highlighter-0.1.6.zip`, проверки структуры и конфигурации успешны с прежней рекомендацией убрать `until-build`. Настоящее наведение в обычной IDE после установки ZIP вручную не проверялось; fixture-тесты используют штатный CtrlMouseData и действие Go to Declaration.

Обращений к internal API и ошибок совместимости нет. Диапазон поддерживаемых сборок 252–263 сохранён; перенос на следующие версии требует повторной проверки этого API.


## Переход из NEON и ограничение работы на наведении 0.1.5

Добавлен `GotoDeclarationHandler` для Ctrl+клика и Go to Declaration на значении `path`. Переход открывает целевой файл, учитывая базовую директорию источника из настроек либо каталог baseline. Используется `LocalFileSystem.findFileByPathIfCached`: обработчик не обновляет файловую систему и не обходит проект. PHP-классы/методы и строки нарушений не ищутся. Новые аннотации, ссылки для всех записей и проходы при открытии документа не создаются.

Навигация и NEON-документация используют общий `BaselineNeonEntryLocator`: ограничены первые 64 строки / 8192 UTF-16 символа заголовка и 32 строки / 32768 символов текущего блока (отдельная строка до 16384 символов). Кэшируются только заголовок и последний блок по modification stamp. Проверяется локальная запись; весь источник по-прежнему валидируется фоновым индексом. Ранее NEON-документация разбирала весь документ при первом запросе — этот разбор удалён. Указатели документации отслеживают диапазон через `SmartPsiFileRange`, не ищут запись по всему файлу после правок.

Синтетическая проверка: 25 000 записей, 2 850 028 символов UTF-16. Холодный запрос к последней записи прочитал **389 символов**. Прогретые 100 запросов с чередованием двух последних записей: **p95 ≈ 0,05 мс** на SDK 252. Тест оборачивает текст документа и запрещает копирование целиком или чтение вне ограниченного окна. Это измерение локального разборщика, без открытия целевого редактора, работы PHP-плагина и общей загрузки IDE.

Четыре новых fixture-теста проверяют регистрацию перехода, данные штатного Ctrl-наведения (в фоновом read action) и фактический Go to Declaration, настроенную базовую директорию, относительные пути, кавычки/табы/BOM/CRLF, несохранённые изменения, отсутствующую цель, каталоги, wildcard-пути и посторонние конфиги. Три проверки разборщика покрывают большой документ, лимиты и локальную валидацию. В plain-text NEON размер Ctrl-подчёркивания определяется IDE и может охватывать весь текстовый элемент; Go to Declaration с клавиатуры не создаёт эту подсветку. Синтаксический анализатор ради изменения подчёркивания не добавлялся.

## Справочник идентификаторов 0.1.3

Тексты файлов были загружены до измерения. Время не включает обход файловой системы, чтение файлов, проверку существования целевых файлов, общий старт IDE и построение PHP PSI. Группировка по файлам включена в оценку памяти, но выполняется после измерения времени создания записей. Память оценивается по разнице занятой JVM-кучи после `System.gc()`; это приблизительный ориентир. Данные Ракеты могут меняться параллельно, поэтому число записей относится к этому прогону.

Микробенчмарк не измеряет полное влияние плагина на память и отзывчивость IDE. При открытии редактора используются готовый индекс и локальный кэш привязки. Фонового polling и запуска PHPStan в реализации нет.
